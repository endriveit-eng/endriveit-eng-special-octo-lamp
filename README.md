# ECフォースメールタスク — Apps Script

Google スプレッドシート「ECフォースメールタスク」の自動化を、Google Apps Script で行うためのリポジトリです。
ソースはここで管理し、[clasp](https://github.com/google/clasp) でスプレッドシートに反映します。

## これは何をするものか

いまスプレッドシートの数式でやっている計算を Apps Script に移します。マニュアルに「触らないでほしい」「壊れます」と書かれている箇所が、そもそも壊れない形になります。

| やること | 対象 |
| --- | --- |
| 次に送るメールの判定 | `03_送信管理` の G〜O列 |
| 抽出データの取り込み | 案件管理シートの A〜H列 |
| 請求金額・書類そろい・停滞日数・アラートの計算 | 案件管理シートの W〜Z列 |
| 今日のタスクをメールで通知 | 毎朝の自動実行 |

## 数式のままと比べて何が変わるか

- **手入力がズレなくなる。** 案件管理シートの手入力欄（★の付いた列）を、行の位置ではなく**受注IDで結び直します**。マニュアルの「ecforceで受注を削除しない。行がズレて、手入力した内容が別の案件のものになります」という事故が起きません。ecforce 側から消えた案件は、消さずに残したうえでアラート欄に `抽出に無し` と出します。
- **「送信済」が推定でなくなる。** `04_送信ログ` に記録がある組み合わせは `送信済`、対応状況からの推定は `送信済(推定)` と区別して表示します。これまでログは件数集計にしか使われていませんでした。
- **表記ゆれで `?` が出にくい。** 対応状況を突き合わせるとき、前後の空白や全角スペースを無視します。
- **経過日数が日付表示にならない。** 数値として書き込み、表示形式も数値に設定します。更新日がシリアル値のまま表示される問題も同じく直します。
- **数式が `#ERROR!` にならない。** 計算列に数式を置かないためです。

## 判定のきまり

### 03_送信管理 のテンプレ欄

`01_運用フロー` が唯一のマスタです。ecforce 側でステージを増減したら `01_運用フロー` を直せば、コードを触らずに追従します。

| 状況 | 表示 |
| --- | --- |
| `04_送信ログ` に記録がある | `送信済` |
| いまの対応状況と同じ段階のテンプレ | `★次` |
| いまより前の段階のテンプレ | `送信済(推定)` |
| いまより後の段階のテンプレ | `-` |
| 見送りの案件 | `-` |
| 対応状況がマスタに無い | `?` |

つまり `商談済` なら T-01 が `★次` になります（マニュアルの「3 商談済 … ここで T-01 を送ります」に合わせています）。

### 案件管理シートのアラート

| 条件 | 表示 |
| --- | --- |
| 契約締結日が入っているのに LINE追加 が「済」でない | `LINE未追加` |
| ecforce の更新日から 7日以上動いていない | `停滞 ○日` |
| 認定日（交付決定日）が入っている | 空欄（完了扱い） |
| 抽出シートから消えた | `抽出に無し（ecforceで受注が削除された可能性）` |

## 使い方

導入が済むと、スプレッドシートの上部に **「運用ツール」** メニューが出ます。

| メニュー | 内容 |
| --- | --- |
| 全部まとめて更新 | 案件管理シートと送信管理を両方更新 |
| 03_送信管理 を更新 | 送信管理だけ更新 |
| 案件管理シート を更新 | 案件管理シートだけ更新 |
| 今日のまとめをメールで送る | 更新してサマリを送信 |
| 毎朝の自動実行をオンにする | 毎日8時台に自動更新＋メール |
| 毎朝の自動実行をオフにする | 自動実行を止める |

週1回の運用（ecforce から CSV を出して `抽出` タブを丸ごと置き換える）はこれまで通りです。貼り替えたあとに「全部まとめて更新」を押してください。

## 導入

はじめて入れるときは **[docs/setup.md](docs/setup.md)** を見てください。スプレッドシートのコピーを取るところから順に書いてあります。

すでに導入済みで、コードを直して反映するだけなら:

```bash
npm install
npm test        # ロジックのテスト
npm run push    # スプレッドシートに反映
```

## 設定を変える

しきい値やシート名は [`src/config.js`](src/config.js) にまとまっています。よく変えそうなところ:

| 変数 | 意味 | 初期値 |
| --- | --- | --- |
| `STALL_THRESHOLD_DAYS` | 何日動かなければ「停滞」とするか | `7` |
| `TRIGGER_HOUR` | 毎朝の自動実行の時間帯 | `8` |
| `SEND_EMPTY_DIGEST` | 何もない日もメールを送るか | `false` |
| `LOST_STATUSES` | 「もう送らない」扱いにする対応状況 | `['見送り']` |
| `DOC_DONE_VALUES` | 書類が揃ったとみなす値 | `['受領', '対象外']` |

シート名やタブ名は変えても動きます。`03_送信管理` は前方一致でも探しますし、案件管理シートはタブ名ではなく見出し（`★労働保険` / `★gBizIDプライム`）で見分けています。

サマリメールの宛先はリポジトリには書きません。Apps Script のスクリプトプロパティ `NOTIFY_EMAILS` にカンマ区切りで設定してください。未設定なら実行した本人に届きます。

## ファイル構成

```
src/
  appsscript.json     Apps Script のマニフェスト
  config.js           設定（シート名・見出し・しきい値）
  utils.js            日付や文字列の共通処理
  flow.js             01_運用フロー（マスタ）の読み込み
  sendManagement.js   03_送信管理 の再計算
  projectSheets.js    案件管理シートの更新
  alerts.js           日次サマリメール
  main.js             メニューとトリガー
test/
  load.js             GAS のソースを Node で読むための足場
  logic.test.js       判定ロジックのテスト
docs/
  setup.md            導入手順
```

## テスト

シートに触らない純粋な関数（段階判定・アラート判定・日付や数値の読み取りなど）を Node で検証しています。

```bash
npm test      # 22件
npm run check # 構文チェック
```

Apps Script のソースをそのまま `vm` で読み込んでいるので、テスト用にコードを二重管理する必要はありません。

## 顧客情報の扱い

**このリポジトリに受注データを置かないでください。** 氏名・メールアドレス・電話番号が含まれます。
`.gitignore` で `*.csv` や `data/` を除外していますが、`git add -f` で強制追加すれば入ってしまいます。
リポジトリに入れてよいのはコードだけで、データは実行時にスプレッドシートから読みます。
