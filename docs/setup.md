# 導入手順

はじめてこのスクリプトをスプレッドシートに入れるときの手順です。
上から順にやれば終わります。作業時間は 20〜30分ほどを見てください。

---

## 0. 先にスプレッドシートのコピーを取る

**これは必ずやってください。**

このスクリプトは `03_送信管理` の G〜O列 と、案件管理シートの列を**上書きします**。
いま入っている数式は消えます。元に戻せるように、先にコピーを作ってください。

1. スプレッドシートを開く
2. ファイル → コピーを作成
3. 名前を「ECフォースメールタスク_導入前バックアップ_2026xxxx」などにして保存

うまく動かなかったときは、このコピーに戻せば元通りです。

---

## 1. 必要なもの

- Node.js 18以上（`node -v` で確認）
- **スプレッドシートの編集権限**
- Google アカウント

編集権限があるかは、スプレッドシートを開いて `拡張機能` メニューに `Apps Script` が出るかで分かります。
出ない場合は閲覧権限しかありません。所有者（kuwa9800@gmail.com）に編集権限をもらうか、
所有者の方にこの手順を実施してもらってください。

```bash
node -v
```

---

## 2. リポジトリを用意する

```bash
git clone https://github.com/endriveit-eng/endriveit-eng-special-octo-lamp.git
cd endriveit-eng-special-octo-lamp
git checkout claude/special-octo-lamp-ogdb2b
npm install
npm test
```

`npm test` が全部通ることを確認してください。

---

## 3. スクリプトIDを調べる

1. スプレッドシートを開く
2. 拡張機能 → Apps Script
3. 開いた画面の左の歯車（プロジェクトの設定）をクリック
4. 「スクリプト ID」をコピー

---

## 4. clasp にログインして紐づける

```bash
npx clasp login
```

ブラウザが開くので、スプレッドシートを編集できる Google アカウントで許可してください。

つぎに `.clasp.json` を作ります。

```bash
cp .clasp.json.example .clasp.json
```

`.clasp.json` を開いて、3 で調べたスクリプトIDを貼ります。

```json
{
  "scriptId": "1AbCdEf...（コピーしたID）",
  "rootDir": "src"
}
```

> `.clasp.json` は `.gitignore` に入っているので、リポジトリには上がりません。

---

## 5. スプレッドシートに反映する

```bash
npm run push
```

`Pushed 8 files.` のように出れば成功です。
上書き確認が出たら `y` を選んでください。

---

## 6. メニューを出す

1. スプレッドシートを開き直す（リロード）
2. 上部に **「運用ツール」** が増えていることを確認

出てこない場合は、Apps Script の画面で関数 `onOpen` を一度手動実行してから、もう一度リロードしてください。

---

## 7. 初回の権限承認

「運用ツール」→「03_送信管理 を更新」を選びます。

はじめての実行では権限の確認が出ます。

1. 「承認が必要です」→ 権限を確認
2. アカウントを選ぶ
3. 「このアプリは Google で確認されていません」と出たら、**詳細** → **（プロジェクト名）に移動** をクリック
   （自分で入れたスクリプトなので問題ありません）
4. 内容を確認して「許可」

このスクリプトが求めるのは次の3つだけです。

| 権限 | 何に使うか |
| --- | --- |
| このスプレッドシートの読み書き | 計算結果の書き込み |
| トリガーの管理 | 毎朝の自動実行 |
| メール送信 | 日次サマリの通知 |

---

## 8. 動きを確かめる

「運用ツール」→「全部まとめて更新」を実行し、次を確認してください。

- [ ] `03_送信管理` の G列に段階の数字が入っている（`?` が出ていない）
- [ ] N列（経過日数）が**数字**で表示されている（日付になっていない）
- [ ] 案件管理シートの受注IDが昇順に並んでいる
- [ ] 案件管理シートの手入力欄（★の列）が、導入前と同じ案件に付いている
- [ ] 停滞日数が数字で出ている

`?` が出た場合は、`01_運用フロー` の対応状況と ecforce の対応状況の文字が違っています。`01_運用フロー` 側を直してから、もう一度実行してください。

---

## 9. サマリメールの宛先を設定する

1. 拡張機能 → Apps Script → 歯車（プロジェクトの設定）
2. 「スクリプト プロパティ」→「スクリプト プロパティを追加」
3. プロパティ名 `NOTIFY_EMAILS`
4. 値にカンマ区切りでアドレスを入れる

```
okada@example.com,moriyama@example.com,kuwahara@example.com
```

設定しない場合は、実行した本人にだけ届きます。

> 宛先はリポジトリには書きません。ここで設定してください。

「運用ツール」→「今日のまとめをメールで送る」で届くか確かめてください。
送るものもアラートも無い日はメールを送りません（`SEND_EMPTY_DIGEST` で変えられます）。

---

## 10. 毎朝の自動実行をオンにする

「運用ツール」→「毎朝の自動実行をオンにする」

毎日8時台に、更新とサマリメールが自動で走ります。
時間を変えたい場合は `src/config.js` の `TRIGGER_HOUR` を直して `npm run push` し、もう一度オンにしてください。

止めたいときは「毎朝の自動実行をオフにする」です。

---

## 導入後の運用

これまでと変わる点は、貼り替えたあとに「全部まとめて更新」を押すことだけです。

| いつ | やること |
| --- | --- |
| 毎日 | 朝のメールか `03_送信管理` の `★次` を見て、ecforce からメールを送る |
| 送ったら | `04_送信ログ` に1行足す（**これまで以上に大事です**。表示に反映されます） |
| そのあと | ecforce 側で対応状況を次に進める |
| 週1回 | ecforce から CSV を出して `抽出` タブを丸ごと置き換え、「全部まとめて更新」 |

## コードを直したいとき

```bash
git pull
# src/ を編集
npm test
npm run push
```

Apps Script の画面で直接編集した内容を手元に持ってくるときは `npm run pull` です。
ただし、手元と画面の両方で直すと衝突するので、**編集はこのリポジトリ側に寄せる**ことをおすすめします。

## 困ったとき

**`Push failed. Errors: ...` と出る**
`.clasp.json` のスクリプトIDが違うか、`npx clasp login` のアカウントに編集権限がありません。

**メニューが出ない**
リロードしても出なければ、Apps Script の画面で `onOpen` を手動実行してからリロード。

**案件管理シートが見つからないと言われる**
案件管理シートは見出しで判別しています。1行目に `★契約締結日` と、`★労働保険`（健康経営）または `★gBizIDプライム`（AI導入補助金）があるか確認してください。

**手入力欄が消えた**
0でコピーしたバックアップから該当列を戻してください。そのうえで、受注IDが両方のシートで一致しているか確認してください。

**アラートに「抽出に無し」が出た**
ecforce 側でその受注が削除された可能性があります。行は消していないので、手入力の内容は残っています。ecforce を確認してください。
